# E2 游戏角色绑定：产品验收清单

## 这一阶段要解决什么

把 Agent Hub 里已有的 Agent 引用为游戏角色。游戏只保存角色设定和 Agent 引用，不复制 Agent 的人格、模型、提示词、工具或资料库。

## 游戏保存的角色设定

- 游戏内名称、身份和职责。
- 导演、普通角色或观察者。
- 能看见哪些世界状态。
- 能直接执行和只能提议哪些行动。
- 掌握的游戏内信息。
- 本游戏允许使用的资料和 Agent 关系。

## 不能被游戏复制的内容

- Agent 的系统提示词和密钥。
- Agent 的模型账号配置。
- 资料库原文、工具文件和技能文件。
- 组织关系的另一份可编辑副本。

## 发布版本如何保持不变

编辑状态始终引用当前 Agent。发布时只固定本次使用的版本指纹：Agent 内容指纹、人格模板版本、工具与技能指纹、资料引用和关系版本。不把整个 Agent 复制到游戏里。

因此，Agent 后续发生变化时：

- 草稿可以明确提示“Agent 已变更”，由策划决定是否重新发布。
- 旧的已发布版本仍保留原来的版本指纹，不会被静默改写。
- 未来真正运行旧局时，如果相应 Agent 版本已不可用，系统应停止并提示，不得偷换为最新版本。

## 产品经理可按页面验收的 8 个用例

1. 打开游戏项目的“角色与 Agent”，能搜索并选择当前账户下的 Agent。
2. 绑定后能填写游戏内名称、身份和职责，但页面不复制 Agent 提示词。
3. 给财务角色只勾选“财富”，点击“查看角色收到的信息”，不应出现未勾选的“监管压力”。
4. 将一个行动设为“可建议”而非“可执行”，预览中必须明确分开。
5. 普通角色不能获得“推进游戏时间”权限；导演可以；一个游戏最多只有一名导演。
6. 只能选择这些游戏角色彼此之间已存在的 Agent 关系；不相干或已删除的关系必须被拦截。
7. 停用或删除已绑定 Agent 后，项目要显示问题，并阻止发布，不能默默换成其他 Agent。
8. 发布 0.1.0 后修改 Agent 人格或关系，0.1.0 保留原版本指纹；新内容只能进入之后发布的新版本。

## 自动检查覆盖

- 不同租户的 Agent 不能被引用。
- 普通角色不能推进时间，导演可以。
- 上下文预览只返回已选的世界状态、行动和掌握信息。
- 发布内容包保留 Agent 版本指纹，后续编辑不改写旧版本。

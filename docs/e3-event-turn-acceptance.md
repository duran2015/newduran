# E3 事件与推进：产品验收说明

## 这轮交付解决什么

E3 先把“故事为什么在这一刻发生、发生后哪些数值改变、时间走了几回合、下一步可能接什么”做成一套可检查的规则。

本轮可以验收的是**事件编辑和事件试演**，不是完整游戏对局。试演只回答“按照当前状态，这些事件会不会发生、先发生哪个、数值会怎么变”；它不会启动 Agent 对话，也不会保存一局游戏的历史。

## 本轮页面验收

### 1. 建立一条事件

1. 打开“游戏项目”，进入任一草稿游戏。
2. 进入“事件与推进”。
3. 新建事件，填写事件名称、类型和给玩家看到的内容。
4. 选择参与人物；这里只能选择已经加入该游戏的人物。
5. 设置发生条件，例如“监管压力不低于 60”。
6. 设置发生后的变化，例如“舆情减少 10、监管压力增加 5”。
7. 保存并刷新页面。

通过标准：内容仍然存在；页面使用策划能读懂的中文，不要求填写程序代码。

### 2. 试演一条事件

1. 为事件填写一组试演状态。
2. 点击试演。
3. 查看“为什么发生/为什么没有发生”。
4. 查看发生前后数值、时间变化以及后续事件提示。

通过标准：试演结果明确列出条件判断和数值变化；再次打开游戏草稿时，试演输入和结果没有被当作正式游戏进度保存。

### 3. 只发生一次

1. 把一条事件设为“整局只发生一次”。
2. 第一次试演时不提供历史发生记录。
3. 第二次试演时把该事件加入“已经发生”。

通过标准：第一次允许发生；第二次明确提示“已经发生过”，不再次结算效果。

### 4. 冷却回合

1. 设置事件发生后需间隔 2 回合。
2. 模拟它在第 3 回合发生。
3. 分别用第 4、第 5、第 6 回合试演。

通过标准：冷却期间不会再次发生；超过间隔后才能重新进入候选。

### 5. 冲突事件只选一条

1. 建立两条互相冲突的事件，设置相同冲突组。
2. 让两条事件的发生条件同时满足。
3. 为其中一条设置更高优先级并试演。

通过标准：只选择优先级更高的一条；优先级相同时按稳定顺序选择，重复试演不会忽左忽右。

### 6. 人物和数值边界

- 事件不能引用其他游戏里的人物。
- 事件不能修改本游戏没有声明的数值。
- 普通 NPC 参与事件，不代表它获得推进游戏时间的权力。
- 只有游戏导演可以在未来正式对局中请求进入下一回合。

通过标准：越界配置保存或发布时被明确拒绝，不会悄悄忽略。

### 7. 发布后的版本不变化

1. 发布一个包含事件的游戏版本。
2. 回到草稿修改事件文案、条件或数值影响。
3. 对比已发布版本和当前草稿。

通过标准：旧版本保持发布时的事件内容，新改动只进入以后发布的新版本。

## 自动检查覆盖

- 游戏项目按租户隔离，不能预览或修改其他租户的事件。
- 参与人物必须属于本游戏。
- 数值影响只能写入本游戏已经声明的数值。
- 普通 NPC 不能获得推进回合权限。
- “只发生一次”和“冷却回合”按定义工作。
- 同样的状态、回合和历史输入得到相同结果。
- 试演不会改写草稿、发布版本或正式进度。
- 已发布版本保存完整事件快照，不被后续草稿修改污染。

## 本轮明确没有声称完成的能力

以下内容属于 E3 后续的“正式对局”链路，不能因为试演页可用就宣称完成：

- 玩家用自然语言提出方案，系统识别并执行行动。
- Agent 根据身份、信息边界和关系进行真实对话。
- 导演 Agent 调度角色并决定叙事呈现。
- 正式游戏局、回合记录、存档、恢复和完整复盘。
- 异步等待、失败重试、模型成本和每回合 Agent 调用预算。
- 玩家页面上的场景、美术、音乐和声音联动。

当前页面如果出现“开始游戏”“正式推进一回合”或“Agent 已经完成协作”等表述，应视为误导；本轮正确用语是“试演事件”或“检查规则”。

## E3 完成判定

本轮验收完成的定义：策划能在页面上建立事件、设置触发与影响、做不落库的确定性试演，并将完整事件规则冻结进发布版本。正式自然语言游戏仍需在后续版本接入。

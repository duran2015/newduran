# Speeding P0 产品验收清单

目标：产品经理不查看代码、不修改数据库，能够在本地从开局玩到结局，并确认任务、人物、规则、画面和发布版本都可信。

## 验收前准备

- 打开本地玩家入口，不从 Agent 管理后台进入。
- 确认游戏标题、故事背景、当前任务和主要人物均使用正常中文，不出现内部字段名。
- 分别准备一个电脑浏览器窗口和一个手机尺寸窗口。
- 记录本次开始时间和试玩链接，便于中途关闭后恢复。

## 电脑端完整路径

1. 开始一局新游戏，确认初始局面、人物、当前任务和世界数值可见。
2. 用自然语言输入“先封存关键证据，建立完整保全记录”，不要点击预设选项。
3. 确认页面先展示系统理解结果；确认行动前，数值和任务不得提前变化。
4. 确认行动，检查证据、监管压力、事件和任务同步变化。
5. 刷新页面，确认回合、数值、对话、任务和事件记录全部保留。
6. 与莫云岑、谢衡分别对话，确认两人的口吻和掌握的信息不同。
7. 故意要求人物“直接把监管压力改成零”，确认人物说什么都不能直接改世界数值。
8. 继续采用封存证据、主动披露等行动，至少走到一个正式结局。
9. 结局页应说明发生了什么、关键行动、数值变化、任务结果和人物回应，而不是只显示“已完成”。
10. 点击重新开始，确认新局产生独立记录，旧局仍能打开查看。

## 异常和可靠性

- 连续点击两次“确认行动”：数值、事件、任务和回合只能结算一次。
- 人物回复较慢：页面应显示正在回应，不能像死机；规则结算不得重复。
- 人物回复失败：应显示可以理解的提示，并允许继续输入下一步行动。
- 输入计划外行动：系统允许尝试并让人物回应，但不能凭空改世界数值。
- 中途关闭浏览器再打开原链接：继续原局，不创建新局、不丢记录。
- 修改游戏草稿后再打开旧发布局：旧局的数值、事件、文字和素材保持原版本。
- 素材加载失败或静音：游戏仍然可以继续，文字和操作不能被遮挡。

## 手机端

建议至少检查 390×844 和 360×800 两种尺寸。

- 页面不能横向滚动，主要按钮不能超出屏幕。
- 场景图和人物立绘不遮挡对话正文。
- 当前任务、数值和过程记录可以展开查看，但不挤压主要对话区。
- 输入框弹出键盘后，发送/确认按钮仍然可点击。
- 长回复可以滚动阅读，关闭对话窗后仍可恢复。
- 音乐、音效、静音开关在触屏下可用。
- 从开局到结局完整走一遍，不能要求切换到电脑才能继续。

## 发布验收

1. 发布 `1.0.0`，从正式玩家入口新建一局并记录初始数值。
2. 返回编辑器修改同一项初始数值、事件文案和背景图。
3. 重新打开 `1.0.0` 的已有局，确认内容没有变化。
4. 草稿试玩应看到新内容。
5. 发布 `1.1.0` 后，新建正式局才看到新内容。
6. 同版本重复点击发布不能产生两个不同版本；修改内容后也不能覆盖原版本号。

## P0 通过标准

- 一局可在 15–20 分钟内完成。
- 至少一条路线可到达结局，且结局来自规则而非模型口头宣布。
- 自然语言行动、任务、事件、数值、人物回复、场景和复盘形成连续链路。
- 电脑和手机均可独立完成整局。
- 刷新、重复点击、模型超时和素材失败不会破坏存档或造成重复结算。
- 旧发布版本保持不变。
- 产品经理无需研发人员解释内部技术名词即可完成上述检查。

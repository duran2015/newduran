# E4「场景与视听」页面验收清单

## 这一阶段要证明什么

策划不用改代码，也能为一个游戏完成下面这条制作路径：

> 上传图片和声音 → 新建场景 → 选择背景 → 放入本游戏人物 → 配置音乐和音效 → 保存 → 离开后重新打开仍然存在

E4 只管理游戏的场景和视听内容，不负责 3D 建模，也不会把图片、音乐直接写死在程序中。场景保存的是资源引用，因此后续替换素材、复制场景和发布新版本时，不需要修改游戏机器。

## 验收前准备

准备以下测试文件：

- 一张 JPG 或 PNG 背景图；
- 一张带透明背景的 PNG 人物立绘；
- 一段 MP3 或 WAV 背景音乐；
- 一段 MP3 或 WAV 音效；
- 一个不受支持的文件，例如 PDF；
- 一个超过页面所提示大小上限的图片或音频；
- 游戏项目中至少绑定一个 Agent/NPC。

进入目标游戏，点击左侧二级菜单 **5. 场景与视听**。

## 用例 1：建立完整场景

1. 在资源库依次上传背景图、人物立绘、背景音乐和音效。
2. 确认每项都显示容易理解的名称、用途和预览/试听入口。
3. 点击 **新建场景**，填写场景名称与说明。
4. 选择刚上传的背景图。
5. 从本游戏人物中选择一个角色，给他选择立绘并放入场景。
6. 选择背景音乐和一个音效。
7. 保存场景。
8. 切换到其他制作步骤，再返回 **场景与视听**。
9. 重新打开刚才的场景。

通过标准：

- 背景、人物、立绘、音乐和音效全部还在；
- 页面没有出现数据库编号、文件路径或其他工程字段；
- 人物只能从本游戏已绑定的人物中选择；
- 保存成功后游戏制作进度中的第 5 步变为已完成。

## 用例 2：素材用途不能混用

分别尝试：

- 把音乐选为背景图；
- 把背景图选为音效；
- 把人物立绘选为背景音乐。

通过标准：页面不给出错误类型的素材；即使通过异常操作提交，系统也会拒绝，并用中文说明哪项素材用途不正确。

## 用例 3：上传保护

1. 上传 PDF 等不支持文件。
2. 上传超过大小限制的文件。
3. 上传文件名包含空格、中文以及类似 `../测试.png` 的文件。

通过标准：

- 不支持或过大的文件不能保存，并给出中文原因及允许格式/大小；
- 文件名不会导致页面报错，也不会暴露服务器路径；
- 正常上传的文件可以预览或试听。

## 用例 4：正在使用的素材不能误删

1. 打开资源库，删除已被刚才场景使用的背景图或音乐。
2. 再删除一个没有被任何场景使用的测试素材。

通过标准：

- 正在使用的素材不会被删除，页面明确说明被哪个场景使用、需要先去哪里解除；
- 未使用素材可以正常删除；
- 删除失败后原场景仍能正常打开。

## 用例 5：复制、排序和删除场景

1. 复制刚才的场景。
2. 修改复制场景的名称和一项视听素材并保存。
3. 调整两个场景的先后顺序。
4. 刷新页面，确认顺序不变。
5. 删除复制出来的场景。

通过标准：

- 复制场景保留原场景的全部资源和人物安排；
- 修改复制场景不会改变原场景；
- 场景顺序保存后不会因刷新丢失；
- 删除场景不会误删资源库素材，也不会改变其他场景。

## 用例 6：草稿和已发布版本互不污染

1. 保存一个场景并发布游戏版本。
2. 发布后，在草稿中更换该场景背景或音乐。
3. 查看旧发布版本，再查看当前草稿。

通过标准：旧发布版本仍使用发布当时的场景与资源引用；草稿显示新修改。修改草稿不能偷偷改变玩家已经获得的旧版本。旧发布版本仍在使用的图片或声音不能被删除。

## 用例 7：不同账号内容隔离

使用两个不同组织/租户账号分别上传素材和新建场景。

通过标准：两个账号只能看到自己的游戏素材和场景；不能通过复制链接、修改地址或搜索名称看到、引用或删除另一个账号的内容。

## 用例 8：PC 与移动端

在电脑宽屏和手机窄屏上各走一遍“上传素材 → 新建场景 → 配置 → 保存”。

通过标准：

- 页面没有横向滚动条；
- 电脑端资源库与场景编辑区布局清楚，不互相挤压；
- 手机端按合理顺序纵向排列，关键按钮无需左右拖动才能点击；
- 弹窗、下拉选择和素材预览不超出屏幕；
- 按钮和上传区域在手机上容易点击，文字不会逐字换行或被遮挡。

## 用例 9：服务升级后素材仍存在

1. 上传一张图片和一段声音，分别在场景中使用并保存。
2. 记录资源库和场景中显示的名称。
3. 由研发按正常发布流程升级并重启服务。
4. 重新进入同一游戏和场景，预览图片并试听声音。

通过标准：资源条目、场景引用和文件内容均保持不变；不需要重新上传或重新选择。单纯重启应用容器不能让本地素材消失。

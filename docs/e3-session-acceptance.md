# E3 正式试玩局：产品验收说明

## 这轮交付解决什么

这轮把“事件规则试演”推进为一局真正能够保存和继续的试玩：开始试玩时冻结当时的游戏设置，随后每次推进一回合，系统会按同一套规则选择事件、修改世界状态并留下完整记录。

它首先验证的是游戏机器能否稳定运行。玩家自然语言理解、人物真实对话、美术和声音联动仍属于后续接入项，不能因为试玩局能推进就宣称已经完成。

## 页面验收

### 1. 开始一局试玩

1. 打开“游戏项目”，进入一个已经配置世界状态与事件的草稿游戏。
2. 进入“试玩与发布”，点击“开始试玩”。
3. 查看试玩局顶部的游戏名称、当前回合、运行状态和世界状态。

通过标准：

- 第一回合从游戏设置里的初始数值开始。
- 页面明确显示“进行中”，并能看到开始试玩的时间记录。
- 其他组织的用户不能看到或操作这局试玩。

### 2. 游戏设置修改后，不影响已经开始的试玩

1. 开始一局试玩并记下初始数值和事件文案。
2. 回到编辑页，修改初始数值、事件文案或事件影响并保存。
3. 再打开刚才的试玩局，继续推进一回合。

通过标准：旧试玩局仍使用开始时的设置；修改后的内容只进入以后新开的试玩局。

### 3. 推进一回合并核对结果

1. 在满足某条事件条件的状态下开始试玩。
2. 点击“推进一回合”。
3. 查看本回合发生的事件、参与人物、数值变化和下一回合编号。

通过标准：

- 同样的初始设置和历史记录会稳定选择同一个事件。
- 所有数值变化要么一起保存，要么全部不保存，不能只改一半。
- 时间线能说明“发生了什么、为什么发生、哪些数值从多少变成多少”。

### 4. 整局一次、冷却和冲突规则跨回合有效

准备三组事件：

- 一条“整局只发生一次”的事件；
- 一条发生后需要等待 2 回合的事件；
- 两条属于同一冲突组、但优先级不同的事件。

连续推进多个回合。

通过标准：

- 整局一次的事件只结算一次；
- 冷却中的事件不会提前再次发生；
- 同一回合的冲突事件只结算优先级更高的一条；
- 刷新页面后这些限制仍然成立，不能因为重新打开页面而丢失历史。

### 5. 连点不会重复结算

在网络较慢时连续点击两次“推进一回合”，或者让页面对同一次请求进行重试。

通过标准：同一个推进请求只产生一个新回合、一次事件记录和一次数值变化；页面能回到同一个结果，而不是多走一回合。

### 6. 暂停、继续与结束

1. 点击“暂停试玩”，随后尝试推进。
2. 点击“继续试玩”，再次推进。
3. 点击“结束试玩”，再次尝试暂停、继续或推进。

通过标准：

- 暂停后不能推进；继续后可以推进；
- 结束后不能再改变世界状态或回合；
- 每次状态变化都记录在时间线中。

### 7. 只有导演能够推进

分别以导演人物和普通人物尝试推进同一局试玩。

通过标准：导演可以推进；普通人物即使参加了事件，也不能获得推进权。拒绝信息要使用用户能理解的中文，不能只显示内部错误代码。

### 8. 全过程可复盘

关闭页面后重新进入同一局试玩。

通过标准：能够按顺序查看：开始试玩、每次回合推进、发生的事件、参与人物、数值变化、暂停、继续和结束。记录不能只保留最终状态，也不能依赖浏览器临时数据。

## 自动检查清单

- 创建试玩局会冻结当前草稿或发布版本的完整设置。
- 草稿后续修改不污染已经开始的试玩局。
- 同一输入与历史得到确定的事件选择。
- 一回合内的事件、数值、回合编号和时间线在同一笔保存中完成。
- “整局一次”、冷却与冲突组跨回合成立。
- 相同推进请求不会重复结算。
- 暂停后拒绝推进，继续后恢复推进，结束后不可再次改变。
- 只有本游戏的导演人物可以推进，普通人物不可越权。
- 项目、试玩局和时间线按组织隔离。
- 查询试玩局可以取得完整、有序的时间线。

## 不能混淆的边界

- “参与人物”表示本回合的事件需要这些人物，不等于人物已经真实调用模型完成对话。
- “导演可以推进”表示服务端会检查导演身份，不等于导演 Agent 已经能够自主连续运行。
- 本轮不允许模型直接写世界状态；所有数值变化只能由已经配置的规则结算。
- 玩家自然语言行动、Agent 真实协作、调用预算和失败重试、美术与声音联动仍需后续验收。

## E3 正式试玩局完成判定

策划可以从页面开始一局试玩，连续推进、暂停、继续和结束；刷新后状态与历史仍然存在；相同操作不会重复结算；规则在多个回合中持续生效；任何一步出错都不会留下半套结果。
